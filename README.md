# EO Inference Toolbox

A QGIS Processing plugin that runs open Earth-observation **foundation models over
your own imagery** to produce dense **per-pixel embedding rasters**, then lets you
explore them with a self-contained similarity / change / classification workbench.

Unlike an embedding *archive* (e.g. Google DeepMind's AlphaEarth, which ships a
global pre-computed dataset), the three models here are **inference backends**: you
give them source imagery — supplied locally or fetched from public STAC catalogues —
and they compute embeddings on the fly.

## Backends

| | Clay v1.5 | Prithvi-EO-2.0 | SatlasPretrain |
|---|---|---|---|
| Maker | Clay Foundation | IBM + NASA | Allen Institute for AI |
| Architecture | ViT + MAE | Multi-temporal ViT + MAE | Swin/ResNet + FPN + head |
| Input | Multi-sensor (S2, Landsat, NAIP, S1) | HLS, 6 fixed bands | S2 (RGB/9-band), S1, NAIP |
| Native res. | Sensor-native (~10 m for S2) | 30 m | ~10 m (S2) / finer (NAIP) |
| Output | Patch/token embeddings | Token embeddings | Multi-scale feature maps (pooled) |
| Licence | Apache-2.0 (code + weights) | Apache-2.0 | ODC-BY (checkpoints) |

All three produce **non–unit-normalised** vectors, so the toolbox L2-normalises every
embedding raster it writes. That keeps the cosine-similarity = dot-product shortcut in
the similarity and change algorithms exactly correct.

## Algorithms (`eoinfer:` provider)

- **Fetch imagery** — pull Sentinel-2 or HLS for an AOI + date range from public STAC.
- **Embed** — run a backend over imagery → an L2-normalised per-pixel embedding GeoTIFF.
- **Embedding → RGB** — PCA-to-3 or band-triplet visualisation.
- **Similarity search** — cosine similarity to a reference point / mean vector.
- **Change / trajectory** — pairwise, trajectory or anomaly change between dates.
- **Classify** — supervised per-pixel classification (opt-in scikit-learn tier).
- **Cluster** — unsupervised k-means segmentation (opt-in scikit-learn tier).

## Dependencies

The plugin **installs and loads with zero third-party dependencies.** Heavy pieces are
opt-in tiers, detected at run time and installed on demand from within QGIS:

- **PyTorch + model weights** — required only to run a backend (the *Embed* step).
  Weights are downloaded on first use and cached; they are never bundled in the ZIP.
- **scikit-learn** — required only for *Classify* / *Cluster*.
- **requests** is used for STAC search if available; otherwise a stdlib fallback is used.

## Installing the plugin

The plugin targets QGIS 3.34 LTR and the QGIS 4.x series (PyQt5 and PyQt6 both work).
Install the built ZIP via *Plugins → Manage and Install Plugins → Install from ZIP*,
or copy the `eo_inference_toolbox/` folder into your QGIS plugin directory and enable
it. It installs with **no third-party dependencies**; add the tier for the backend you
want to run later, from the wizard's **Backends** tab. The first *Embed* run downloads
that backend's weights and caches them — Clay's checkpoint is about 5.2 GB, so budget
time for it. The [user guide](docs/USER_GUIDE.md) has the wizard walkthrough, the
manual / GPU install path from a terminal, and troubleshooting.

## Checking it works

A quick post-install confidence check (the full release checklist is
[`docs/SMOKE_TEST.md`](docs/SMOKE_TEST.md)):

1. **Loads clean.** With no torch/scikit-learn installed, the plugin still enables
   without error, the **EO Inference** provider shows all seven algorithms in the
   Processing Toolbox, and the toolbar button opens the wizard with the tiers shown as
   *missing*.
2. **A tier installs.** Install a backend from its card; the badge turns green when it
   finishes. If a badge stays red for a backend you did install, confirm it imports
   from *Plugins → Python Console* (`import claymodel` / `terratorch` /
   `satlaspretrain_models`) — the Embed step runs off that import regardless of the
   badge.
3. **A run completes.** Fetch a small scene, embed it, and run Similarity — one full
   pass end to end.
